# ARKI D6.4 — Ingestión multimodal de fuentes y Visual Field

## Estado

**Implementado y validado localmente**, sujeto a la disponibilidad del Core autenticado para probar persistencia remota. La integración reutiliza el router visual existente, el snapshot de SICL y el almacenamiento configurado; no crea un segundo Core ni un segundo motor visual.

## Flujo

`CÁMARA / ARCHIVO / PDF → storagePut → SOURCE_INGESTED → OCR / extracción textual → observaciones AI_PROPOSED → resumen editable → revisión humana → promoción explícita`

Las fuentes se guardan con `sourceId`, clave y URL de media, tipo de captura, MIME, fecha, ámbito espacial, provenance y resultado OCR. El endpoint `visualField.ingest` devuelve la versión del proyecto y marca siempre `humanReviewRequired = true`.

## OCR y documentos

El adapter `server/arkiOcr.ts` utiliza `pdftotext` cuando el PDF contiene capa textual y `pdftoppm + tesseract` cuando el PDF es escaneado. Para imágenes aplica Tesseract y registra idioma, motor, confianza, página, región y provenance. La extracción es provisional: no convierte texto OCR en FACT.

## Separación epistemológica

Las observaciones visuales se etiquetan como `AI_PROPOSED`; los campos ambiguos permanecen como `UNKNOWN`; el sistema no crea decisiones ni promoción automática. El usuario puede revisar y editar el resumen antes de continuar.

## Limitaciones actuales

La confirmación humana y la promoción a `FACT` aún requieren una acción explícita en SICL Core. La identificación de parcela, coordenadas, datum, escala y jurisdicción no se infiere automáticamente: se captura como contexto declarado o UNKNOWN. La clasificación de tablas y estructura documental es provisional.
