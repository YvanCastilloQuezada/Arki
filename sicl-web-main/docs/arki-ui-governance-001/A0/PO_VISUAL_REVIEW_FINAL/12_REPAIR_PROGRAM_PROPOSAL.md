# Future repair program proposal — not executed

The dependency order should be: (1) technical foundation and source/build hygiene; (2) lazy-route loading and chunk observability; (3) authorized Core and authentication dependencies; (4) safe functional control exercises; (5) visual/UX refinements; and (6) accessibility/responsive verification.

The first wave should verify the current runtime with persisted network and console evidence. It should not redesign screens or alter authority gates. The second wave can repair only confirmed route-loading defects. Core/auth work requires explicit configuration and human authority. Functional controls should be classified only after non-destructive action tests. Visual changes should wait until the route is known to render and its primary architectural purpose is understood.
