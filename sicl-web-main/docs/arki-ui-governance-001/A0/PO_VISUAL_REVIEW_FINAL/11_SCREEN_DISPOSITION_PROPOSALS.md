# Non-binding screen disposition proposals

These are proposals for a future product wave. None was executed.

Rendered screens should generally be **KEEP** while the runtime baseline is stabilized. Design Funnel, Parametric Generator, Family Studio and BIM Viewer have enough visible architecture-specific content to remain the reference surfaces. The Help and federation surfaces should be reviewed after their dependency/auth states are reproducible. Lazy routes and unobserved routes are **INSUFFICIENT_EVIDENCE**, not redesign candidates. The Core 503/fail-closed states should be **KEEP AS SAFETY STATES** until a real Core transport is authorized.
